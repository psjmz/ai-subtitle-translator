模型 A（默认）

会合并进发给该模型的请求体（如 qwen3.x 需要 enable_thinking:false 来关掉思考，否则容易超时）。留空 = 不附加。禁止覆盖 model / messages / stream / temperature / max_tokens。

模型 B（可选）

配好后在下面的「语言分流」里勾选要走模型 B 的目标语言；未勾选的语言、以及模型 B 没配全时，一律走模型 A。

模型 C（可选）

参数结构与模型 B 完全相同。分流优先级 C > B > A：勾给 C 的语言走 C，没勾 C 的才看 B，都没有就走 A。C 没配全、或没勾任何语言时，C 完全不参与（默认留空，先配参数再挑语言试点）。

模型 D（Gemini 免费额度池）

三个 key 顺序使用：前一个到当日上限才动下一个，不是轮询。模型池按从上到下的顺序用：上一档的 key 全用满，才降下一档。单个 key 到「每分钟」上限只是跳过它、不退役；全池（所有档 × 所有 key）都到「每日」上限才回退到 C / B / A。RPM / RPD 请照 Google AI Studio 速率限制页显示的数字填 —— 填大了会撞 429（能兜住，但白跑一趟），填小了会提前停用免费额度。

模型 E（网页 Gemini · 独占通道，优先级最高）

这里是自建的网页版 Gemini 通道（new-api → 桥接 → gemini.google.com）。它同一时刻只服务一个翻译任务：别的任务一旦判定「E 正忙」，整程自动走 D / C / B / A，不排队、不报错。分流规则和 C / B 完全一样：只有下面「语言分流」里勾给 E 的语言才会走它，一门都不勾 = E 不接管任何语言。网页通道单批约 6–7 秒，这不是故障。
两个数都只约束同一个任务自己：到顶了就等几十秒重发同一批，不会降级换模型（一集里前后两个模型语气会跳）。实测单批 6–7 秒，间隔设 2 秒平时几乎不会真正触发，它只是保险丝。
