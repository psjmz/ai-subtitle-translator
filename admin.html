模型 A（默认）

会合并进发给该模型的请求体（如 qwen3.x 需要 enable_thinking:false 来关掉思考，否则容易超时）。留空 = 不附加。禁止覆盖 model / messages / stream / temperature / max_tokens。

模型 B（可选）

配好后在下面的「语言分流」里勾选要走模型 B 的目标语言；未勾选的语言、以及模型 B 没配全时，一律走模型 A。

模型 C（可选）

参数结构与模型 B 完全相同。分流优先级 C > B > A：勾给 C 的语言走 C，没勾 C 的才看 B，都没有就走 A。C 没配全、或没勾任何语言时，C 完全不参与（默认留空，先配参数再挑语言试点）。

模型 D（Gemini 免费额度池）

每把 key 对应一个 Google 项目，模型挂在 key 底下。调度从上到下：Key 1 的模型依次用满，才动 Key 2，最后才回退 C / B / A。同一把 key 内 RPM 满只等一分钟、不退役；所有 key 的日额度都到限才跨槽。RPM / RPD 照 Google AI Studio 速率限制页显示的数字填 —— 填大了会撞 429（能兜住，但白跑一趟），填小了会提前停用免费额度。
—
这个数只拦新任务：桶里有名额才把新任务分给 D，空了就让给 C / B / A，不排队。已经分到某一格的任务不受它限制——只要日额度还有，桶空了也照样发（超出的次数单独计数），否则一集里会中途换模型。用不完的会攒着（最多攒 3 小时），深夜攒下的正好留给白天高峰。名额是整个 D 槽共用。填 0 = 关闭此闸，仍受每档的 RPD 约束。
只填 1~2 把 key 也能用。⚠️ Google 的额度按项目算、不按 key 算：三把 key 要分别属于三个项目才是三份额度；建在同一个项目里的多把 key 共享同一份，轮换会一起失效。

模型 E（网页 Gemini · 独占通道，优先级最高）

这里是自建的网页版 Gemini 通道（new-api → 桥接 → gemini.google.com）。它同一时刻只服务一个翻译任务：别的任务一旦判定「E 正忙」，整程自动走 D / C / B / A，不排队、不报错。分流规则和 C / B 完全一样：只有下面「语言分流」里勾给 E 的语言才会走它，一门都不勾 = E 不接管任何语言。网页通道单批约 6–7 秒，这不是故障。
两个数都只约束同一个任务自己：到顶了就等几十秒重发同一批，不会降级换模型（一集里前后两个模型语气会跳）。实测单批 6–7 秒，间隔设 2 秒平时几乎不会真正触发，它只是保险丝。
窗口内（含两端）E 不接新任务，整程走 D / C / B / A —— 晚高峰 Google 网页端单批会涨到几分钟，等了也白等；已在跑的 E 任务不会被中途切断。连续超时把 E 判死后，全局冷却期内新任务也直接走 D，不再重复交学费；E 一旦成功立刻解除冷却。

记录走站点默认模型（云端翻译）的会话元数据：文件名、目标语言、字幕条数、所用模型、完成/下载状态；不记录字幕内容。自带 API Key 的翻译直连服务商，仅在完成/下载时上报轻量记录（模型/语言/下载状态可统计，批次与时长不适用）。同 IP 同文件同语言 30 分钟内算一次会话。「导出格式」读的是各格式的累计次数（同一任务先下 SRT 再下 ASS 会记两次）。「槽」是这单由哪个模型槽承担（E 网页 Gemini → D 免费池 → C → B → A 兜底），数字是批次数；一单中途额度耗尽会换槽，换过就并排列出（如 D×12 C×3）。自带 Key 不占本站槽位，早期记录没有槽位标记，显示「-」。
